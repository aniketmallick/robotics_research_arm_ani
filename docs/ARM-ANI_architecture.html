The trust layer · in Python, not the prompt
🚦 Five gates decide if — and how — to act
G1
Seen?
"There's no red block here."
G2
Ambiguous?
"Two cups — which one?"
G3
Reachable?
"I've no taught pick for there."
G4
Confident?
"34%. Approve? …no answer → stand down."
G5
Verified?
"Got it. Confirmed."
Gates live in our code, wrapped around the action — a prompt jailbreak cannot move the arm past one. The 10-second stand-down is a Python deadline, not the model choosing to wait. Fail-closed by default.
▼ only a satisfied gate proceeds
Body · motion
🦾 Motion worker → SO-101 arm
One thread owns the arm; long actions run async so the robot talks while it moves. A grasp = replay of a human demo taught at that spot (learn-from-demonstration).
LeRobot 0.5.2 · SO-101 follower · taught-zone replay
▼
Audit
📊 Decision log → live "robot's mind" dashboard
Every tool call, gate decision, confidence number, approval and outcome is written to an append-only JSONL trail — the audit artifact and the screen the room watches.
👁️ Perception — feeds G1 · G2 · G5

A single fixed webcam frame → Gemini Robotics-ER 1.6 identifies the named object (open-vocabulary) and a pixel zone-map assigns it to a marked spot. Confidence comes from agreement across independently-worded queries, not a made-up number.

🛡️ Safety spine — wraps every motion

Two-tier joint-limit clamps, speed-limited interpolation, workspace bounds, a freeze-first kill switch, and operator-presence checks. Nothing reaches a motor un-clamped; every default is fail-closed.
